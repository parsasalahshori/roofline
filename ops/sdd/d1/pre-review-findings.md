## Important
1. NOTE (relay-server.ts): a pre-auth /relay slot exhaustion DoS takes down AI calls for every company. RELAY_MAX_UNAUTH=50 is process-wide, and a denied socket keeps its slot until 'close'. ws waits up to 30 s for the peer's close frame, so 50 sockets that never answer it hold every slot with no token at all, and a token of the right shape adds the 5 s setup on top. Twilio then gets a 503, /after-relay with no HandoffData is taken as 'end', and the call hangs up. Fix: in deny(), uncount() and ws.terminate(); better, verify the HMAC + relayCallById + the mandatory X-Twilio-Signature in onUpgrade and answer 401 before handleUpgrade.
2. NOTE (calls repo/engine; you already have it): calls.conversation_id is never written, so after-call summarises nothing and texts every answered caller "sorry we missed your call". Also: spam mark, inbox call cards and stats are wrong.
3. NOTE (after-call.ts/relay-server.ts): after-call runs ~5 s after every relay close, including a transfer hand-off (ringing_team) or message mode (still 'ai'). That sends a wrong text-back while the call is still live, writes a summary of half a call, sets status 'ended' too early, and bills only the first segment (the second hits ON CONFLICT DO NOTHING). Fix: return early unless the call's status is terminal.
4. NOTE (relay-server.ts/recording.ts/engine): a second relay session on the same call (message mode after a failed transfer) starts a new conversation and a new recording and forgets the caller's recording objection, which is a recording-law problem. Both recordings write to recordings/<co>/<callId>.mp3, so one is lost. Fix: skip start() when recording_status is stopped_by_caller; seed transcriptOff from the call; reuse the linked conversation; put the recording SID in the key.
5. NOTE (relay-server.ts): calls.transcript_stored is never set true (default false; only recording.ts writes it, to false). The inbox shows "not kept" for every voice turn and Haiku summaries get an empty transcript. Tests seed it true by hand. Fix: set it true together with status 'ai' on authenticate.
6. NOTE (texts.ts/engine): every fd-text job builds a fresh state with nextPosition 0, so from the 2nd exchange on insertTurn hits conversation_turns(conversation_id, position) unique, the error is swallowed, and turns, tool calls and URGENT flags are lost. turnLimit also never trips for SMS. Fix: seed nextPosition/turns from max(position)+1, or allocate the position in insertTurn under a row lock.
7. NOTE (state.ts/engine.ts): system-note ordering can poison a call. An interrupt, then another interrupt before any reply, gives `user, system(note), user`; per the API rule a mid-conversation system entry must be last or followed by an assistant turn, so every later request is a 400. That means 2 model errors and a hand-off, and two such calls trip the per-process breaker (Ruling DQ) for every tenant. PLAUSIBLE (API rule; ScriptedLlm can't catch it). Fix: push pending notes only immediately before llm.answer(); test that no system entry is ever followed by user.
8. NOTE (tools/caller.ts, texts.ts): verify_caller has no real lockout (attempts 4, 5, … still run verifyCustomerByNameStreet), and over SMS identity and the failure count reset with every text. conversations.identity is never written. Fix: refuse at count >= MAX; persist identity and failures on the conversation and restore them in texts.ts.
9. NOTE (engine.ts/caller.ts): identity and customer_id are never saved to the conversation row for calls (only a booking fills them in). The owning rep never sees the call in the inbox, after-call writes no timeline activity, and text-back gets no customerId.
10. NOTE (tools/message.ts, after-call.ts): take_message writes conversations.summary, which after-call uses as its "done" marker. Any message-taken call gets no summary, no 'call' timeline activity and is never ended, and its summary is the caller's raw words even after a recording objection. Fix: give after-call its own marker, or don't write summary.
11. NOTE (tools/message.ts, Ruling EA): take_message still overwrites a job's next step for a phone-matched (unverified) caller.
12. NOTE (calls repo + twilio-voice.ts): the AI call cap. (a) countLiveAiCalls counts only status 'ai', which is set ~1 s+ after the TwiML, with no lock, so a hail burst overshoots max_concurrent_ai_calls (Opus spend). (b) It has no age bound and nothing sweeps stuck rows: a deploy during calls loses the status callbacks, the rows stay 'ai' forever, and after 4 such rows every call for that company goes to team/voicemail permanently. Fix: an advisory lock + reservation in the hook; bound by started_at > now-35 min; an fd-health pass ends stale ringing/ai/ringing_team calls and enqueues after-call.

Fix: US NANP via textability() (no toll-free or 900), and refuse the company's own Roofline/business numbers.
14. FIX: two quick first texts from a number with no active thread. FOR UPDATE locks nothing, the 2nd insert hits conversations_active_sms_uniq, and the whole /sms tx rolls back (including insertInboundText). Twilio doesn't retry, so the text is lost from the CRM. Same after a 24 h gap. Fix: an advisory lock per company+phone before the select.
15. FIX: missed-call text-back creates duplicate customers (findOrCreateCallerCustomer check-then-insert without createCustomer's per-phone lock). 17. FIX (gate-request.ts + text-back.ts; NOTE for texts.ts): replies and text-backs go to the customer's primary number, not the number that called or texted. The AI's reply with booking details can go to a different person. Fix: an optional toE164 override in buildGateRequest when it is one of the customer's phones (the opt-out check on that number). I add the override and use it in text-back; texts.ts should pass conversation.phoneE164 (T19).
18. FIX (routes/conversations.ts + web): a blocked or scheduled staff reply looks sent. Fix: show the reason/schedule, and don't flip handling when nothing was sent.
19. FIX (route) / NOTE (texts.ts): a staff reply silences the assistant forever. The reply sets handled_by='team' and team_until=+2h, texts.ts skips handledBy==='team', and nothing reads team_until. The separate lastTeamReplyAt check already gives the 2 h quiet. Fix: the reply route stops setting handled_by (the manual "Team is handling" switch stays open-ended, per spec).
20. NOTE (larger): staff replies, and inbound texts the assistant skips, never appear in the conversation detail (it is built from conversation_turns only). Fix: write team/caller turns, or build sms detail from messages + tool cards.
21. FIX (web): the owner override has no UI, and the on/off switch locks when blockedReason is set even while Front Desk is on, so nobody can turn the AI off. Fix: disable only when turning ON is blocked and the user is not the owner; owner confirms and sends override: true.
