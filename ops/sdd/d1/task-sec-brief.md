### Task SEC: voice webhook and relay socket hardening (security review, D1 part)

**Base:** `d1-front-desk` 4ce5c7f. From a read-only review of the voice hooks and the `/relay` socket against `ops/sdd/integration/security-review.md` (origin/f2-shell). Signing and tenant binding were found sound; fix these:

1. **Medium — /relay memory DoS before auth** (`apps/api/src/front-desk/relay-server.ts:47`, `:196`): `new WebSocketServer({ noServer: true })` keeps ws's default 100 MiB `maxPayload`, and frames that arrive while authenticating are pushed to an unbounded `queued` array. Fix: `maxPayload: 64 * 1024`; deny (close 1008) when `queued.length` would exceed 32; cap the number of sockets that are not yet authenticated (e.g. 50 per process; refuse the upgrade with 503 beyond it). Tests: an oversized frame closes the socket; a flood before setup closes with 1008; the pre-auth cap refuses extra upgrades.
2. **Low — relay token after the call ended; replayed voice webhook mints new tokens** (`relay-server.ts:130-144`; `hooks/twilio-voice.ts` around `insertCall`): deny the socket (1008) when the call row's status is `ended`, `failed` or `rejected`; in the voice hook, answer with relay TwiML only when the call row was created by this request or is still `ringing` (a replay of a call already in progress or ended gets `<Response><Hangup/></Response>`); validate `CallSid` against `/^CA[0-9a-f]{32}$/` on every voice route (400 otherwise), as the SMS hook validates `MessageSid`. Keep the no-answer path working: `/voice-transfer/after-dial` reconnects the relay for the SAME call in message-only mode — that path mints its token itself and the call status there is `ringing_team`/`transferred`, so the deny list must not include those. Tests: replayed signed /voice for an ended call gets Hangup; a token for an ended call is refused; a malformed CallSid is 400; the after-dial message-only reconnect still works.
3. **Low — spoofed caller ID marks forwarding verified** (`front-desk/forwarding-test.ts:116`): besides `From === TWILIO_TEST_CALLER_NUMBER`, require either `ForwardedFrom` equal to the company's business phone or `StirVerstat` starting with `TN-Validation-Passed`. Pass those fields from the voice hook's signed body. The owner override (Task 18) remains the escape hatch when a carrier sends neither. Tests: spoofed call (no ForwardedFrom, no passing verstat) does not verify; ForwardedFrom match verifies; verstat pass verifies.
4. **Low (cost) — forwarding test dials premium/non-US numbers** (`forwarding-test.ts:58/69`): refuse business phones in `TOLL_FREE_AREA_CODES` or `NON_US_NANP_AREA_CODES` (packages/shared/src/phone.ts) with 422 field `phone` and a plain module-constant message before `placeTestCall`. Test it. Owner to-do (ledger, not code): Twilio voice geo-permissions on the master account.
5. **Test gaps:** a tampered `?c=` on the recording hook is 403; a tampered `?company=` on the whisper routes is 403; an unsigned `/voice-status` is 403.

Not in scope: the per-process one-socket-per-call registry (one always-on API host; ops note only).
