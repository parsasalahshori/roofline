**1. Daily nudges (`runClaimsDaily(deps, companyId, meta)`, fired by T3's `claims-daily` job at 10 AM local):**
- First: return when the company status is not `active`/`trial` (no agents for trial_ended/past_due/canceled), and — until T15 wires pause — read A1's `agent_settings` row for `claims`: a missing row means **paused** (Ruling GX-E) → return. (T15 replaces this read with the shared `isPaused`; keep it in one helper `claimsAgentOn(tx, ctx)`.)
- Idempotent per local day: if an agent task `agent='claims', kind='claims_nudges'` was created today (company zone), return.
- Candidates (`claims-agent.ts`): claims whose job's customer has a mobile phone, with `claimNudgeDue(facts, now, company_settings.claims_nudge_days)` (T2a) ≠ null, where `inspectedAt` = the job's latest completed `inspection` appointment end, `adjusterAt` = the claim's adjuster appointment start (or null). Then `followUpAllowed(kind 'claims')` with the customer's log, last inbound and last storm text (T5's repo functions). Cap 25 per run (one `draftTexts` call).
- Drafting: `deps.llm.draftTexts({ instruction: 'claims_ask_filed' | 'claims_ask_adjuster_date' | 'claims_ask_outcome', facts })` grouped by kind (one call per kind present). Every returned body passes D1's `guardSentence` (each sentence, no hits) and `claimsGuard`; a job missing from the result, or failing those checks, or an `LlmUnavailableError` (incl. refused) gets the template for its kind (in `nudges.ts`, plain, ≤ 300 chars, e.g. "Hi {first}, it's {rep} at {company}. Have you had a chance to file your insurance claim? If so, reply with the claim number and your insurance company."). When any text came from a template, the task summary says "Written from a template" (plan Ruling 3).
- One task via `createTask(…, { allowInternalStepTypes: true })`: `agent 'claims'`, `kind 'claims_nudges'`, title "Claim check-ins ({n} texts)", one `send_personal_texts` step `{ purpose: 'informational', kind: 'claims', messages, dedupePrefix: 'claims:{localDate}' }`, `expiresAt` = 6 PM local today. No task when there are no candidates.

**2. Replies (`onClaimsReply(tx, deps, msg)` — the hook's in-transaction call, Ruling GX-A):**
- Quick read only: the customer had a `claims` follow-up within 7 days (`follow_up_log`) and has a claim not `closed` → `deps.jobs.send('claims-reply', { companyId, messageId }, { singletonKey: messageId })` and return `{ consumed: false }` (the reply also continues to Front Desk: until D1 T14 lands there is nothing after this block; D1's later continuation rule — consumed only when extraction fully answered — moves into the job, see below). Anything else → `{ consumed: false }` with no job. Must not throw for ordinary input.
- The `claims-reply` job (`agents/claims/replies.ts` `runClaimsReply(deps, companyId, messageId)`): loads the message body, `deps.llm.extractClaimReply({ text, now, timeZone })`; on `LlmUnavailableError` stop quietly (the reply still reaches people in the inbox). With facts: `saveClaim(..., { actor: 'agent', userId: null })` (T6) applying `claimNumber`/`insurer` when empty or different, and `decision` → status (`approved`/`partly_approved`/`denied`) only when `canMoveClaim(from, to)` (T2a); then one **live** task (`mode: 'live'`, `agent 'claims'`, `kind 'claims_reply_noted'`, title "Claims noted claim number 0451-22" / "Claims noted the adjuster visit" etc., no steps that text anyone — a `demo_noop`-free task: use the task service's live/no-step path if one exists, else a single internal step type already allowed for live tasks; read how A1/D1 record live notes and follow it). An `adjusterAt` drafts a **needs-approval** task with one `create_appointment` step `{ jobId, kind: 'adjuster', start: adjusterAt, end: +60 min, userId: job's rep (or the owner), note: 'From the homeowner's text' }`.
- Front Desk continuation (D1 T14 `queueFrontDeskText` / "Thanks, got it."): not built yet → leave `// D1 T14: queueFrontDeskText(...)` at the spot with a ledger carry; do not send any text from this job.

**3. `create_appointment` handler (`agents/appointments-steps.ts`):** re-checks the assignee's availability at run time (`findSlots`-style busy check over `listBusyBlocks` + appointments for that user; a conflict → `{ status: 'failed', errorPlain: "That time isn't free any more." }`), then C1's `createAppointment(tx, ctx, { jobId, kind, startsAt, endsAt, assignedUserId: userId, notes: note, source: 'scheduler' … })`, sets `claims.adjuster_appointment_id` (+ status `adjuster_scheduled` via `saveClaim` actor agent when the claim is earlier in the flow), and `deps.jobs.send('calendar-push', { companyId, appointmentId }, { singletonKey: appointmentId })`. Idempotent on rerun (look for an appointment already created by this step: store the id in the step result and reuse it). Result `{ created: 1 }`.

**Never:** text or email an insurer or adjuster (only customer ids are recipients); write coverage/deductible language (guards).

**Tests (CI):** nudges — the three kinds with their day thresholds, paused (no agent_settings row) → nothing, already-ran-today → nothing, spacing blocks a customer texted 2 days ago by Follow-up, template fallback when `ScriptedLlm` throws (summary says "Written from a template"), a guard-failing draft falls back; replies — the hook sends a job only within 7 days of a claims text, the job updates the claim (events by agent) and makes the live note and an adjuster appointment draft, an unparseable/unavailable extraction changes nothing; create_appointment — creates, pushes, sets the claim's appointment, refuses a busy slot, rerun creates nothing new.
