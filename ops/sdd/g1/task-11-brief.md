**Weather watch (`runWeatherWatch`, T3's `scheduler-weather` job at 6 AM and 2 PM local):**
- Company active/trial and agent `scheduler` on (T10's `schedulerAgentOn`; GX-E). At most one open weather task per company: skip when an agent task `agent 'scheduler', kind 'weather_moves'` was created in the last 6 hours or is still `draft`/`awaiting_owner` (a 2 PM run after an untouched 6 AM task does nothing new).
- Candidates: `scheduled`, not archived, `kind 'install'` appointments starting in the next 3 local days, with a property that has coordinates and an assigned user. One `hourly` read per property (cache by rounded lat/lng within the run); `weatherRisk` with the company's `weather_rain_pct` / `weather_gust_mph` and the company work hours (company_settings; member hours when C1 has them). A null forecast skips that install (never guesses).
- For each risky install: the next workday (company work hours; not the same day; within 14 days) where the forecast is clear (when the forecast reaches that far: NWS hourly covers about 7 days; beyond it, a free day counts as clear and the step's `reason` says "No forecast yet for {day}") **and** the assigned user is free all day (`listBusyBlocks` + that user's appointments; all-day range like C1's installs: same `allDay`/start/end shape as the original). No such day → leave that install out and mention it in the summary ("1 install has no clear day in the next two weeks").
- One task per run when any move was found: `agent 'scheduler'`, `kind 'weather_moves'`, title "Rain on Thursday — move 2 installs?" (wind: "Wind on …"; several days: "Bad weather this week — move 3 installs?"), `expiresAt` = the earliest original start. Steps: one `move_appointment` per install (`reason` e.g. "70% rain 10 AM–2 PM Thursday"), then one `send_personal_texts` step `{ purpose: 'informational', kind: 'reminder', messages, dedupePrefix: 'weather:{localDate}:{runHour}' }` telling each customer with a mobile phone the new date (drafted with `draftTexts({ instruction: 'weather_move', facts })`, guards as T10's `bodyOk`, template fallback "Hi {first}, it's {company}. Rain is forecast on {old day}, so we'd like to move your roof install to {new day}. Reply here or call us if that doesn't work."). Customers hear only after approval (the texts step runs after the moves).

**`move_appointment` handler (`agents/appointments-steps.ts`, next to T8's `create_appointment`; replace the `notBuilt` line in `tasks/handlers.ts`):** re-check at run time that the appointment is still `scheduled`, still assigned to `userId` and the target range is still free for that user (else `{ status: 'failed', errorPlain: "That day isn't free any more." }` or "That install was changed since this plan was made."); then C1's `updateAppointment` with the new start/end (keep allDay), set `moved_by_task_id` = the step's task id, push to calendars, result `{ moved: 1 }`. Idempotent: a rerun that finds the appointment already at the target range with `moved_by_task_id` = this task returns `{ moved: 1 }` without another update.

**Never:** cancel an appointment; text a customer before approval.

**Tests (CI):** risky install (rain and wind separately) → task with a move to the next clear free workday and a text; a busy next day is skipped for the following one; a null forecast and a clear forecast make nothing; paused → nothing; the 2 PM run after an open 6 AM task makes nothing; template fallback; the handler moves, sets moved_by_task_id, pushes, refuses a busy or changed appointment, and a rerun does not move twice. Use `FakeWeatherSource.hourlyValue` from T9.
