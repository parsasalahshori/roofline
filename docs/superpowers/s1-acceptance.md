# S1 acceptance map: Storm Scout

This maps every clause of spec section 12 (`docs/superpowers/specs/2026-10-12-roofline-storm-scout-design.md`, "Acceptance criteria (S1)") to the tests that prove it.

How to read it: each table row is one clause of the bullet. "Tests" lists the file, then the test name in quotes exactly as written in the file (`test(`/`it(`/`def test_`). The hail worker, contour areas, the 30-minute cadence, match timing and ad sync are proven by pytest and API/db integration tests, not by browser tests (Plan Ruling 11). Browser tests live in `apps/web/e2e` and run only on CI (`Platform E2E Hail`). Paths are relative to the repository root. API and db tests need a database and run on CI.

E2E names used below:

- `apps/web/e2e/storm.spec.ts`: "storm plan in 2 clicks"; "office approves messages, owner approves spend".
- `apps/web/e2e/doors.spec.ts` (phone project): "rep marks a door Wants a check and the lead reaches the rep Today"; "landing page on a phone submits a request".
- `apps/web/e2e/a11y.spec.ts`: "storm window has no serious accessibility violations"; "storm detail has no serious accessibility violations"; "route view has no serious accessibility violations"; "storm landing page has no serious accessibility violations".
- `apps/web/e2e/phone.spec.ts`: "S1 pages do not scroll sideways".
